# 数据存储说明

## 1. 当前存储架构

当前项目不是通过仓库中的 MySQL SQL 脚本保存分析结果。运行时数据主要保存在 n8n Data Tables；AI 缓存代理单独使用 SQLite。

| 存储 | 用途 | 数据是否随仓库分发 |
|---|---|---|
| n8n Data Table：`pm_review_items` | 保存问题洞察、正向洞察及 PM Review 状态 | 否，保存在 n8n 实例中 |
| n8n Data Table：`analysis_run_status` | 保存分析批次的运行状态和错误摘要 | 否，保存在 n8n 实例中 |
| n8n Data Table：`positive_overall_reports` | 保存每批次的正向整体报告 | 否，保存在 n8n 实例中 |
| SQLite：`ai_cache` | 保存通过代理校验的模型响应缓存 | 否，运行时位于 Docker 数据卷 |

## 2. n8n Data Tables

### `pm_review_items`

保存当前批次的 Product Insight 及审核字段。关键关联字段包括：

- `analysis_run_id`：分析批次 ID。
- `final_cluster_id`：最终 Cluster ID。
- `review_key`：批次与 Cluster 组合形成的记录键。
- `insight_type`：区分问题洞察与正向洞察。
- `batch_write_complete`：批次写入完成标记。
- 审核状态及 PM 修改内容：供前端查看、通过、修改或驳回洞察。

### `analysis_run_status`

记录分析批次状态，供前端轮询和错误处理工作流使用。常见状态包括 `running`、`completed` 和 `failed`。

### `positive_overall_reports`

按 `report_key` 保存每个批次的正向整体报告，包括报告 JSON、批次 ID 及相关计数信息。

### 导入注意事项

工作流 JSON 中包含当前 n8n 环境的 Data Table ID。导入到其他 n8n 实例后，需要核对或重新选择对应的 Data Table，不能假设 ID 在不同环境间通用。

## 3. AI 缓存 SQLite

缓存代理默认使用：

`/data/cache.sqlite3`

缓存表：

`ai_cache`

缓存 Key 由命名空间、请求阶段、完整请求体和可选阶段版本共同决定。只有通过代理校验的阶段才会写入缓存。

当前代理支持的 **8 个有缓存阶段**（其中两项单条阶段是兼容保留）：

- `quality`（旧单条阶段，兼容保留）
- `quality-batch`（当前批量质量筛选）
- `issue`（旧单条阶段，兼容保留）
- `issue-batch`（当前批量 Issue 拆解）
- `clustering`
- `global-consolidation`
- `problem-insight`
- `positive-insight`

`positive-overall` 正向整体报告阶段绕过缓存，不读取或写入该阶段缓存；报告格式由 n8n 中的解析与校验节点负责检查。

SQLite 文件应保存在 Docker 持久化数据卷中，不应提交到 GitHub，也不应与原始评论或报告混为一谈。

## 4. 数据与安全原则

- 仓库不包含真实评论样本、导出的分析结果或 SQLite 缓存文件。
- 不把 `.env`、API Key 或其他凭据提交到版本控制。
- `.env.example` 仅提供配置项示例，部署前需要复制为 `.env` 并填入自己的密钥。
- 清空 AI 缓存不会删除 n8n Data Tables 中已经保存的洞察与报告。
