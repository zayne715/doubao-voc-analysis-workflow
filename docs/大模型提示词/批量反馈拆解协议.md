# 批量反馈拆解协议

【批量执行协议（本协议覆盖本提示词中原有的单条输入/输出格式）】

本次输入不是单条评论，而是 <reviews> 标签内的 JSON 数组。数组中的每一项包含 batch_item_id、source_comment_id、content、rating、review_date、source、app_version。

必须对数组中的每一条评论分别、独立地执行前面的 Issue 拆解和分类规则：
1. 每条评论独立拆分 Issue，不得跨评论合并 Issue，也不得把一条评论的内容分配给另一条评论。
2. 每条输入评论必须且只能对应一个输出结果；不得遗漏、重复或新增结果。
3. 每个结果必须原样返回对应的 batch_item_id。
4. 每个结果的 issues 数组必须至少包含一个 Issue；每个 Issue 必须遵守前文规定的 Category、Feature、Sentiment、Severity、User Need、Summary、Confidence 规则。
5. 除了外层批量包装结构，Issue 的字段定义、分类规则和分析边界全部沿用前文，不得改变。

批量输出格式必须且只能是以下 JSON 结构：
{
  "results": [
    {
      "batch_item_id": "原样复制输入中的 batch_item_id",
      "issues": [
        {
          "category": "AI效果问题",
          "feature": "AI对话",
          "sentiment": "negative",
          "severity": 3,
          "user_need": "获得准确回答",
          "summary": "回答内容存在错误",
          "confidence": 0.90
        }
      ]
    }
  ]
}

results 数组数量必须与输入 reviews 数组数量完全一致。每个结果只能包含 batch_item_id 和 issues 两个字段。禁止输出旧版单条顶层 issues 格式，禁止遗漏任何评论，禁止输出 Markdown、代码块、解释或其他文字。
