# 数据采集说明

## 1. 数据来源

当前主工作流采集豆包在腾讯应用宝中的公开评论：

- 来源：应用宝
- 应用包名：`com.larus.nova`
- 排序：按评论时间获取最新评论
- 单页请求量：10 条
- 启动参数 `limit`：10–1000 的整数

采集接口与请求字段由主工作流中的 `Generate Pages` 和 `HTTP Request1` 节点维护。接口结构可能变化，实际执行前应通过 n8n Execution 检查返回数据。

## 2. 当前工作流采集步骤

1. `Generate Pages` 校验 `limit`，按每页 10 条计算页数。
2. `HTTP Request1` 通过 POST 请求应用宝评论接口。
3. `Normalize Reviews` 从响应的 `data.components[*].data.itemData[*].comment` 中提取评论字段。
4. `Deduplicate & Limit Reviews` 跳过空评论、按 `source_comment_id` 去重，并按请求数量截断输出。

当前请求地址在工作流中配置为：

`https://yybadaccess.3g.qq.com/v2/dc_pcyyb_official`

该接口属于当前实现依赖；若接口不可用或返回结构变化，需要更新并重新测试工作流。

## 3. 标准化字段

| 字段 | 来源 / 处理方式 |
|---|---|
| `source_comment_id` | 应用宝评论 ID |
| `content` | 评论原文，去除首尾空白，不改写正文 |
| `rating` | `mulDimensionScore.total`，无法取得时为空 |
| `review_date` | 将接口提供的 Unix 秒级时间戳转换为 `Asia/Shanghai` 时间 |
| `source` | 固定为 `应用宝` |
| `app_version` | 当前接口解析逻辑没有取得该字段，因此为空 |

空评论会被跳过；如果评论 ID 存在，则使用评论 ID 去重。不同评论 ID 的相同文本不会仅因为文字相同就自动删除。

## 4. 数据完整性边界

当前导出的工作流会限制最多输出请求数量，但没有独立的“实际数量必须等于请求数量”的最终 Guard 节点。因此：

- `limit=50` 表示最多输出 50 条有效且去重后的评论；
- 如果接口返回不足、过滤后数量不足，工作流可能得到少于 50 条的结果；
- 不应仅凭工作流执行成功就认定已经拿到请求的全部数量，应检查 `Deduplicate & Limit Reviews` 的实际输出条数。

若业务要求严格采集满指定数量，应另行增加采集完整性检查，并明确处理接口确实没有更多评论的情况。

## 5. 采集合规与安全

- 只处理当前工作流可以访问的公开评论数据。
- 不在仓库中保存真实评论 CSV、Excel、用户分析结果或运行缓存。
- 工作流当前包含一个用于请求的固定 `PhoneGUID` 值。公开仓库前应确认它不是个人或生产环境专属标识；若需要替换，必须在真实环境重新测试采集接口。
- 不要将 API Key、Cookie、Session 或其他凭据写入工作流 JSON、前端代码或文档。
